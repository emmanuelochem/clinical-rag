# Deploying to Google Cloud Run (free tier)

The app deploys as **one container**: the Next.js frontend is public on Cloud Run's port, and the
FastAPI backend runs privately inside the same container. Synthetic patients, the search index and
the embedding/reranker models are **built into the image**, so a new instance serves immediately
and no database or disk is needed.

| Setting | Value | Why |
|---|---|---|
| CPU / memory | 1 vCPU / 2 GiB | Measured peak ≈ 560 MiB; headroom for spikes |
| Min / max instances | 0 / 1 | Scales to zero when idle; caps worst-case cost |
| Billing | Request-based (default) | You pay only while a request is being processed |
| Region | `europe-west1` | Tier 1 region (free-tier pricing applies); change with `REGION=` |
| Keep-alive | Cloud Scheduler → `/api/keepalive` every 10 min | Keeps the instance warm; ~7 billed minutes/month |

## What you need

- A Google account with a **billing account** (a card is required even for the free tier).
- Your Groq API key (free: https://console.groq.com/keys).

## Deploy (about 15 minutes, mostly waiting for the build)

1. **Create a project** at https://console.cloud.google.com/projectcreate and link your billing
   account to it. Note the **project ID**.
2. **Open Cloud Shell** (the `>_` icon at the top right of the console). It already has `gcloud`,
   `git` and `python3`.
3. **Clone the repo.** The repo is private, so use a GitHub personal access token as the password
   when prompted (https://github.com/settings/tokens, scope `repo`), or make the repo public:

   ```bash
   git clone https://github.com/emmanuelochem/clinical-rag.git && cd clinical-rag
   ```

4. **Run the deploy script** (replace the project ID; paste your key when you run it):

   ```bash
   export GROQ_API_KEY=gsk_your_key_here
   export PROJECT_ID=your-project-id
   ./deploy/cloudrun.sh
   ```

   The script enables the required APIs, stores the key in **Secret Manager** (never in the image
   or the repo), builds the image with Cloud Build, deploys it, creates the keep-alive job and
   prints your public URL, e.g. `https://clinical-rag-xxxxxxxx.europe-west1.run.app`.

5. **Set a budget alert** so you are emailed before any charge. In the console:
   *Billing → Budgets & alerts → Create budget*, amount **$1**, alerts at 50% and 100%.
   Or from Cloud Shell:

   ```bash
   gcloud billing budgets create --billing-account="$(gcloud billing projects describe "$PROJECT_ID" --format='value(billingAccountName)' | cut -d/ -f2)" \
     --display-name="clinical-rag" --budget-amount=1USD --threshold-rule=percent=0.5 --threshold-rule=percent=1.0
   ```

To **update** after pushing changes: `git pull` in Cloud Shell and run the script again (it reuses
the stored key and the keep-alive token).

## Keep-alive (external cron)

`GET /api/keepalive?token=<token>` keeps the instance warm and, on a freshly started instance,
loads the models and search index (≈3 s) so visitors never pay that cost. Subsequent calls return
in milliseconds. The token is generated by the deploy script and stops strangers from triggering
warm-ups; `GET /api/ping` is an open, no-op liveness check.

The script schedules it with **Cloud Scheduler** (3 jobs per billing account are free). To use an
external cron instead, for example **cron-job.org** or **UptimeRobot** (both free), point a 10-minute
job at the keep-alive URL the script printed, then delete the Cloud Scheduler job:

```bash
gcloud scheduler jobs delete clinical-rag-keepalive --location europe-west1
```

Keep-alive makes warm instances very likely, not guaranteed: Google may still recycle an idle
instance. A cold start takes about 7–10 seconds.

## Cost

Free tier per month (request-based billing, verify on https://cloud.google.com/run/pricing):
180,000 vCPU-seconds, 360,000 GiB-seconds and 2 million requests. With 1 vCPU and 2 GiB that is
about **50 hours of active request processing per month**. A visitor exploring the app uses a minute
or two; keep-alive pings use about 7 minutes in total. Idle time is not billed.

Other small costs: the image (~1.9 GB) is stored in Artifact Registry, where 0.5 GB is free; the
rest costs roughly $0.10 per GB per month. Secret Manager and Cloud Scheduler usage stay within
their free tiers.

`--max-instances 1` caps the worst case. If someone kept the instance busy 24/7 for a month, it
would cost tens of dollars, which is why the budget alert matters.

## Limitations of the free setup

- **Data resets** when an instance is replaced: uploaded documents and the audit log are kept in
  the instance's in-memory filesystem. The bundled synthetic data is always present.
- **Uploads process slowly**: with request-based billing, CPU is throttled after a response is
  sent, so background indexing of uploaded documents can stall. For a demo, rely on the bundled
  knowledge base, or deploy with `--no-cpu-throttling` (instance-based billing; costs more).
- The app has **no login**: anyone with the link can use it and your Groq free-tier quota.

## Remove everything

```bash
gcloud run services delete clinical-rag --region europe-west1
gcloud scheduler jobs delete clinical-rag-keepalive --location europe-west1
gcloud secrets delete groq-api-key
```

Then delete the image under *Artifact Registry → cloud-run-source-deploy* in the console.
